# 2026-11-04 15:26 EST: Fix the final branch review's findings

## Summary

The final whole-branch review of cargo-testcache v1 reproduced three wrong skips and one race,
each breaking the promise that the tool never skips wrongly. A change to Cargo's `[env]`
configuration still skipped. A via-cargo pass could be recorded for a different binary than the
one hashed. Input globs with `..` or `./` matched nothing, silently. A binary relinked during the
run could be recorded under the old binary's key. This round fixes all four, each with a test
that fails without the fix, and makes the reviewer's smaller cleanups.

## Decisions

1. Cargo configuration is keyed coarsely: one digest of every file and `--config` value, so any
   config change reruns everything. An unreadable config file makes the key unavailable. A
   `--config` value that names an existing file reads that file, as Cargo does.
2. An `[env]` table is found by parsing with `toml`. A file or value that does not parse, or
   cannot be read, counts as having one. The via-cargo fallback is the same as for a configured
   target runner.
3. Under `--via-cargo`, a binary whose one-target build does not report the hashed executable
   still runs, so the user gets results. It is never recorded. `run_whole` runs the user's own
   arguments and needs no check.
4. `..` is resolved only before a glob's first wildcard; `..` after one is refused.
5. After a pass, the executable and spawned binaries are hashed again. Input files are not,
   because an edited input is recorded with its old digest and so reruns next time anyway.
6. The shared record path went into the re-hash commit, since that commit rewrote both copies.

## Not done

- Shared libraries in build-script link-search directories are not keyed: a rebuilt `.so` that
  a test loads at runtime, with an unchanged test executable, can be skipped wrongly.
- With several `--target`s, `package_bins`, `build_scripts` and records are last-wins per
  package and target.
- Hashing the `inputs` files has no progress bar.
- A runner in `.cargo/config.toml` (`target.<triple>.runner`) changes the key but is still not
  applied by the direct runner; only `CARGO_TARGET_<TRIPLE>_RUNNER` and `[env]` force Cargo.
- Configuration from `CARGO_*` environment variables (other than `CARGO_HOME`) is not keyed.
- Records written with key format 1 fail to parse and are dropped with a warning each, once,
  on the first run after this change.
